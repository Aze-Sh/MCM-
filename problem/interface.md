# 模拟器接口与计费

依据 [附件1](appendix-1.docx) 和 [附件2](appendix-2.docx)。原件保留，提取文字位于 `text/`。实际启动方法见 [运行说明](../docs/running.md)。

## 四条接口

默认地址 `http://127.0.0.1:2026`，仅本机访问；全部使用 POST，Content-Type 为 `application/json`，请求体为无 BOM 的 UTF-8 JSON。

共同字段：`arena_id="default"`、`robot_id=当前登录队号`、`request_id=该动作唯一标识`。`/measure`、`/clear` 另需 `position={"x":数值,"y":数值}` 与 `channel=1..20`。

| 接口 | 作用 | 接受后状态/时间变化 |
|---|---|---|
| `/enter` | 开始运行 | 初始位置 (0,0)、频道 1；不增加虚拟时间；读取 `remaining_real_duration_s` |
| `/measure` | 移动并检测目标频道 | 路程/5 + 切频 0 或 1 + 检测 5 秒；更新位置及测向机频道 |
| `/clear` | 移动并尝试清除指定频道源 | 路程/5 + 失败 3 秒或成功 5 秒；更新位置，不改变测向机频道 |
| `/exit` | 主动结束 | 不增加虚拟时间；成功返回 `exit_reason="user_exit"` |

`/measure` 的 `measure_result` 为 `direction`、`near`、`no_signal`。仅 `direction` 有 `svd_deg`；`near` 表示辐射范围内且距离不超过 5 m，可在当前位置尝试清除。`/clear` 的 `clear_result` 为 `success` 或 `no_target_in_range`。

## 实现约束

1. 逐次收到完整 HTTP 响应后再发新动作，不并发发送动作；每次检测无需在现实中等待 5 秒。
2. 网络超时或连接中断时，对未确认动作只重试完全相同的路径、正文、request_id。相同 ID 与内容返回原响应，不重复计时。不同动作使用新 ID；同一 ID 改内容会触发 409。
3. 同时检查 HTTP 状态和 `accepted`；HTTP 200 不保证执行成功。`accepted=false` 的 `virtual_time_s=0` 不能用来重置本地状态，应保留最近一次已接受状态。
4. 不添加未声明字段，包括 position 内的额外字段。坐标必须有限、分量绝对值≤2000000；频道为 1—20 的整数。
5. 使用 `/enter` 返回的实际剩余时间控制截止并留出退出余量；不能固定假设有 1200 秒。测试结束后接口关闭，不调用 `/exit` 查询结束原因。
6. 仅在已确认接受后更新位置、频道、累计清除数和时间；同一动作重试返回的旧响应不能二次计入清除数。
7. 示向度保留两位小数。理论题按 ±1° 分析；工程端可为量化误差增加保守裕量，但需明确这属于实现假设，不能宣称附件规定为 ±1.005°。
8. 保存本地动作及响应日志；模拟器的加密正式日志仍须另外原名导出。日志中的队号属于本地接入信息，提交前需要单独按规则核对匿名要求，不能修改官方要求保留的原始加密日志。


## 计费核对例子

进入 → 在(300,400)测频道1 → 原地测频道2 → 到(300,0)清除频道3且失败 → 原地测频道2 → 退出，累计虚拟时间为0、105、111、194、199、199秒。清除不改变测向机频道。

程序默认使用本地127.0.0.1接口，不会启动模拟器或选择界面模式。运行期间保留模拟器自身的数据目录；它不是本仓库的实验缓存。
